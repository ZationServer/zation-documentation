# Project Structure

This chapter gives you an overview of the structure of a server project generated by the CLI.

```
myServer
├── src
│   ├── index.ts
│   ├── configs
│   │   ├── index.ts
│   │   ├── app.config.ts
│   │   ├── server.config.ts
│   │   └── services.config.ts
│   └── app
│       ├── index.ts
│       ├── auth
│       │   ├── index.ts
│       │   └── Login.ts
│       └── profile
│           ├── index.ts
│           └── GetProfile.ts
├── test
│   └── test.ts
├── Dockerfile
├── package.json
└── tsconfig.json
```

## index.ts

The `src/index.ts` file is the main entry point of your project.
It imports the configurations (which import the components) and launches the server:

```typescript
import launch from "zation-server";

import "./configs";

launch();
```

The `launch` function returns a promise that resolves when the server is launched. 
By default, the process exits with code 1 when the launch fails (`terminateOnLaunchError`).

## configs

The `configs` folder contains all configurations. Every configuration is registered with the static `Config` class:

**server.config.ts**  
Describes the settings of the server itself: port, hostname, TLS, origins, auth options, panel, logging, cluster join token.

**app.config.ts**  
Defines everything about your app: user groups, default component configurations, events, middlewares, background tasks and allowed client systems. 
It also imports the `app` folder so that all components get registered.

**services.config.ts**  
Contains the definitions of services (e.g. database connections) that are created before the server starts.

Read the [Configurations](guides/server/configurations.md) chapter for details.

## app

The `app` folder contains your components (Controllers, Receivers, Databoxes and Channels) grouped by feature.
Every feature folder exports a `Router` which is combined to a root router in `app/index.ts`:

```typescript
import { Router } from "zation-server";
import { authRouter } from "./auth";
import { profileRouter } from "./profile";

const rootRouter = new Router();

rootRouter.use(authRouter);
rootRouter.use(profileRouter);

rootRouter.register();
```

The routes are combined to the endpoint identifiers, e.g. `auth/login` and `profile/get`.
Read the [Components](guides/server/components.md) chapter to learn how components are registered.

## test

The `test` folder contains mocha tests based on the `zation-assured` package. See [Testing](guides/server/testing.md).

## Dockerfile

The generated multi-stage `Dockerfile` builds the project and creates a slim production image with a health check.
See [Running in Production](guides/runningInProduction.md).
