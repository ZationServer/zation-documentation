# Scaling Horizontally

A single Zation server runs on one CPU core. To handle more clients, run multiple server instances and connect them to a cluster.
Inside a cluster, channels, databoxes, background tasks (`clusterSafe`), auth tokens and the bag functions (disconnect/deauthenticate) work across all instances.

## Architecture

A cluster consists of three kinds of processes:

| Process | Package | Default port | Description |
| --- | --- | --- | --- |
| State server | `zation-state` | 7777 | Coordinates the cluster: registers brokers and servers, elects the leader, shares auth options. Exactly one instance. |
| Broker | `zation-broker` | 8888 | Forwards published messages between the servers. One or more instances. |
| Server | `zation-server` | 3000 | Your application server. As many instances as you need. |

Clients connect to the servers through a load balancer (e.g. NGINX or a cloud load balancer with WebSocket support). Sticky sessions are not required.

## State Server

```bash
npm i zation-state
SECRET=mySecret PORT=7777 node node_modules/zation-state/dist/run.js
```

Environment variables: `SECRET`, `PORT` (7777), `SERVER_PATH` (`/`), `LOG_LEVEL`, `SCALE_DELAY` (100 ms). Docker secrets are read from `/run/secrets`.
The state server logs its join token at start. The format is `<secret>@ws://<host>:<port>[/path]`.

## Brokers

```bash
npm i zation-broker
JOIN="mySecret@ws://10.0.0.5:7777" PORT=8888 node node_modules/zation-broker/dist/run.js
```

Environment variables: `JOIN` (or `SECRET` and `STATE`), `PORT` (8888), `SERVER_PATH`, `LOG_LEVEL`.
Brokers can be added or removed while the cluster is running; the servers rebalance their connections automatically.

## Servers

Set the `join` option in the server config of every instance:

```typescript
Config.serverConfig({
    id: process.env.SERVER_ID,
    port: 3000,
    join: process.env.JOIN_TOKEN,
    clusterShareTokenAuth: true,
    brokerClusterClientMaxPoolSize: 12
}).register();
```

The `id` must be unique per instance (a random id is generated by default).
With `clusterShareTokenAuth` (default `true`), the auth options of the first server are shared with all servers so that tokens are valid everywhere.

## Cluster-Aware Functions

```typescript
bag.clusterLinked;   // true when the server has joined the cluster
bag.clusterLeader;   // true on the leader server

// these work on all servers
bag.disconnectUser(userId);
bag.deauthenticateUser(userId);
chatChannel.publish(member, event, data);
profileDatabox.content(member).update(data);
await profileDatabox.close(member);      // forEveryServer defaults to true
```

Databoxes fetch the last transaction of other servers when a member is initialized (`fetchLastTransactionData`) to avoid unnecessary reloads.

## Docker Compose Example

```yaml
services:
  state:
    build: ./zation-state
    environment:
      SECRET: ${CLUSTER_SECRET}
  broker:
    build: ./zation-broker
    environment:
      JOIN: ${CLUSTER_SECRET}@ws://state:7777
    depends_on: [state]
    deploy:
      replicas: 2
  server:
    build: .
    environment:
      MODE: p
      JOIN_TOKEN: ${CLUSTER_SECRET}@ws://state:7777
      AUTH_SECRET: ${AUTH_SECRET}
    depends_on: [state, broker]
    deploy:
      replicas: 4
```

The `zation-state` and `zation-broker` repositories contain a `Dockerfile` that can be used to build the images.
